# ひとさじ

自炊に、ちいさな火を。

ひとさじは、今日作れそうな一品を決め、写真で「つくれた」を残す自炊習慣アプリ。料理の完成度より、自分のために作った一歩を大切にする。

## 届けたい価値

対象は、一人暮らしを始め、自炊を続けたい学生や社会人。料理が嫌いというより、帰宅後に献立を考える余裕がない、食材を使い切れない、いつも同じものになってしまう人を想定する。

「検索して選ぶ」「買うものを考える」「作れなかった自分を責める」という負担を小さくする。今日の余裕と家にある食材から、一歩目を具体的にする。

利用者が得たい変化は、記録数そのものではなく「今日はこれなら作れそう」「自分にもできる」「また作ろう」と思えること。この効果は検証中の仮説である。

## 世界観

- 名前：**ひとさじ / HITOSAJI**。小さな行動と、料理の身近さを重ねる。
- 合言葉：**がんばりすぎず、つくりつづける。**
- キャラクター：料理の火をかたどった、小さな相棒。達成を喜び、休みを受け止める。
- 見た目：生成り、セージグリーン、焼き色のオレンジ。食卓に置いたノートのような温度感。
- 言葉遣い：指導や採点より、次の一歩を具体的に。レンジ調理や簡単な一品も自炊として扱う。

## 基本体験

1. **決める**：調理時間を5・15・30分から選び、手元の食材を登録する。
2. **作る**：おすすめの一品を開き、材料と短い手順を確認する。手順にはチェックを付けられる。
3. **残す**：写真を選び、料理名・ジャンルを確認する。ひとことは任意。
4. **積み重なる**：継続日数、経験値、料理ジャンルが更新される。
5. **つながる**：今日の記録で仲間の食卓がひらく。他の一皿からレシピへ進める。

記録は献立を選ばず直接始めることもできる。調理時間と、献立決め・記録にかかる操作時間は別の指標として扱う。

## 現行ルール

### 献立

- 調理時間の上限を厳守する。
- 手元の食材の充足率を優先し、直近3日のジャンルと異なる料理を少し優先する。
- 調味料は在庫判定に含めず、レシピ内で別に示す。
- 「買い足しなし」は登録済みの主材料がすべてそろうことを指す。
- 候補がない場合は空状態を表示し、条件を広げられるようにする。
- 3食提案は最大3品。5分以内など候補が少ない条件では、存在する候補のみを出す。
- 3食の実施日は固定しない。予定変更や外食があっても順番を選び直せる。

### 記録

- 写真1枚、料理名、料理ジャンル、公開範囲を保存する。ひとことは任意。
- 写真がない体験用に、料理イラストを使うサンプル入力を用意する。
- 写真はJPEG・PNG・WebP、15MB以下。長辺800px以下のJPEGに変換して端末に保存する。
- 分類は「ごはん」「麺」「炒めもの」「スープ」「蒸しもの」の5種類。
- 料理名と分類は必ず利用者が修正できる。写真からの自動認識は現在接続されていない。
- 1日に複数の料理を記録できる。経験値の付与は最初の記録だけ。
- 現行プレビューでは、保存後の編集・削除、過去日への記録、複数写真は未対応。

### 継続

- 毎日方式：日本時間の日付単位で記録する。今日が未記録なら、昨日までの連続を表示する。
- 日付を進め、前日が未記録かつ休みの保護もないと継続が途切れる。
- おやすみチケットは最初に2枚。1日1枚でその日を保護する。
- 休みは継続を切らさないが、継続日数を増やさない。
- チケットを使った日に料理を記録したら、チケットを返し、通常の記録日になる。
- 記録済みの日、チケット使用済みの日、残り0枚の日は使用できない。
- 週目標方式：月曜〜日曜のうち3日記録すれば達成。複数記録や休みを追加の日数に数えない。
- 週目標ではチケットを使わない。毎日方式で既に使ったチケットの履歴は保持する。

プレビューの日付は初回に日本時間から設定し、その後固定する。実験室で翌日へ進めることで、同じ条件を再現できる。

### 経験値

| 条件                                     | 報酬                          |
| ---------------------------------------- | ----------------------------- |
| その日最初の記録                         | 20 XP                         |
| 初めてのジャンル                         | さらに10 XP                   |
| その日の2件目以降                        | 0 XP、記録は保存              |
| 減点方式で、直近3日に同ジャンルが2件以上 | その日最初の記録を10 XPに変更 |

同じ料理名かどうかではなく、編集後のジャンルで判定する。ジャンルが広すぎる場合の不公平さも検証対象となる。仕様を切り替えても、既に記録に付与されたXPは書き換えない。

### 食卓と公開範囲

- 「自分だけ」「匿名でみんな」「友達だけ」を一皿ごとに選ぶ。
- 既定値は「自分だけ」。食卓への公開と食卓の閲覧権を分ける。
- 記録で解放する方式でも、非公開の記録で閲覧できる。公開を必須にしない。
- おやすみチケットだけでは食卓を解放しない。翌日は再びその日の記録が必要。
- いつでも閲覧する方式は、他の人の料理を先に見て献立を決められる。
- プレビューでは、匿名・友達向け記録を自分の食卓に表示する。「自分だけ」は表示しない。
- 友達間の配信、認証、アクセス制御、実際の公開は未実装。いいね・フォローも端末内の状態であり、相手への通信はない。

## 比較する5つの仮説

| 論点             | A                | B                | 判断に使う観察                             |
| ---------------- | ---------------- | ---------------- | ------------------------------------------ |
| 献立を決める単位 | 今日の1択        | 次の3食          | 決定時間、変更回数、予定への負担           |
| 継続の単位       | 毎日 + 休み      | 週3日の目標      | 再開したい気持ち、休んだ後の離脱           |
| 同じ料理への反応 | 新しい挑戦に加点 | 繰り返しを減点   | 自炊そのものを避けないか、挑戦したくなるか |
| 食卓の入口       | 記録してから閲覧 | いつでも閲覧     | 記録の動機になるか、献立決めに役立つか     |
| おたよりの口調   | やさしい提案     | 継続のリマインド | 心地よさ、通知を止めたくなるか             |

既定は「今日の1択」「毎日 + 休み」「挑戦への加点」「記録で解放」「やさしい提案」。通知はアプリ内文面の比較に限定される。

## 次の展開

### 継続が助かることを確認してから広げる

1. **食材を使い切る献立**：数日の料理を、共通の食材でつなぐ。量・期限の入力負担と、買い物負担の減少を比較する。
2. **写真からの下書き**：料理名とジャンルの候補を作る。間違いをすぐ直せることを優先し、栄養・衛生・加熱状態の断定はしない。
3. **家族からの一品**：家族がレシピ候補を送り、本人が選ぶ。監視にならない通知・既読・共有範囲を設計する。
4. **小さな料理スキル**：「包丁なし」「食材を使い切った」「ひとつ鍋」など、献立以外の成長を記録する。
5. **仲間の小さな輪**：ランキングより、少人数の近い生活リズムの人から一品を見つけられる関係を試す。

### 事業としての仮説

無料では記録と基本提案を提供し、有料では食材の使い切り、先の献立、買い物のまとめなど、意思決定の負担を減らす機能を候補とする。継続の喪失を避けるための課金は既定の設計にしない。

別の仮説として、大学生協・学生寮・新生活支援との連携を検討する。利用者と支払者を分ける場合は、導入先が何を改善したいのか、費用をかける理由があるかを確認する。広告、価格、契約、継続率、市場規模について確定した事実はまだない。

AI費用は「提案1回」「写真候補1回」の原価と使用回数、保存費用は画像数と保持期間から積み上げる。価格の決定より先に、利用頻度と支払い意思を確認する。
