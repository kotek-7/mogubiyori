# ひろばの全面フィールドUI

ひろばではカヤ村を画面全面の下地にし、なかまと料理をその場所に置く。財布、育成状態、ナビゲーションは村に重なる小さな道具として画面端にまとめる。中央下のなかまと、大きな器を添えた赤い食事ボタンを体験の焦点にする。

本書は実画面の調査に基づく全面フィールドの構成・材質と、対応する実装・受入条件を記す。共通の色・形・操作状態は[ゲームUIの設計](game-ui-design.md)、場面の意味は[世界設定](world.md)、文言は[UI文言ガイド](ui-writing.md)を参照する。既存のマリオ作品の参照はメニュー・選択・文字の原則として維持し、本書はフィールド上の構成を補う。

## ゲーム画面の観察と採用

以下は公式サイト・公式ストアに掲載された特定の静止画の観察であり、作品全体のUI仕様ではない。「採用」は本作への設計判断を示す。各作品の素材、キャラクター、固有の枠や配色を複製するものではなく、掲載画像から公式の色値を認定するものでもない。

### ピクミン4：世界の周辺に役割を分散する

[任天堂の若葉ガイド](https://www.nintendo.com/jp/switch/ampya/guide/index.html) — [ロックオン中の実画面](https://www.nintendo.com/jp/switch/ampya/guide/img/guide_point_image09.jpg)

**観察**：フィールドが画面全体の下地。左上に日時計、右上に資源の数値、左端に仲間の顔と短い体力、右下に隊列がある。現在の「なげる」は操作人物の近くに置かれる。数字と記号は背景に埋もれない輪郭を持つ一方、各群をまとめる大きな常設パネルはない。人物、仲間、敵の大きさと地面への影が、フィールド内の距離と対象を伝える。

**採用**：財布・育成・移動先を別の小さな群にまとめ、中央のなかまと村を空ける。育成の対象を顔や名前に結び付け、食事の操作と対象の対応が分かる位置に置く。時計や顔を含む図案には機能上の意味を持たせる。戦闘用の照準、色使い、機械的な計器の形は持ち込まない。

### あつまれ どうぶつの森：必要な道具だけを開く

[任天堂のパーティーモード説明](https://support-jp.nintendo.com/app/answers/detail/a_id/36834) — [フィールド](https://support-jp.nintendo.com/euf/assets/images/nintendo/36834/36834_12.png)・[スマホを開いた画面](https://support-jp.nintendo.com/euf/assets/images/nintendo/36834/36834_01.png)

**観察**：確認したフィールド画面では左上のスマホ、右下の地図、人物の頭上の小さな印が重なり、中央の広場は大きく残る。スマホを開くと左に一枚の道具面が現れ、右の人物と村は見えるまま。人物が持つスマホと、画面に開く道具の関係が分かる。赤い矢印と赤枠はサポート記事の注釈であり、ゲームUIの観察には含めない。

**採用**：ひろばに情報の一覧を常設せず、詳細は必要なときに開く。表示中も対象のなかまと村の位置関係を残す。人物の顔や選択の印を使い、常時の説明文を増やさない。あつ森のスマホや地図をそのまま置くのではなく、カヤ村の器・手帳・市場の道具で役割を表す。

### Ooblets：道具ごとの形でHUDをまとめる

[公式Steamストア](https://store.steampowered.com/app/593150/Ooblets/) — [町の実画面](https://shared.akamai.steamstatic.com/store_item_assets/steam/apps/593150/ss_af9919821684499bb80bb35140426138b3405fab.1920x1080.jpg?t=1696517972)

**観察**：左上に手帳、右上に時計とメーター、左下に短い目的と食べ物、下端中央に道具がある。町と行列のなかまが画面の大部分を占め、手前の木や柵が奥行きを作る。手帳、時計、皿、道具列はそれぞれの対象に合う形で、同じカードの反復にはなっていない。文字や数字は短く太く、世界の細部と見分けやすい。

**採用**：数値のために村を狭めず、役割が同じ情報だけを小さくまとめる。器の食事ボタンは道具として大きく見せ、財布は所持数を読むための小さな群にする。前景は空間を作るために使い、操作や顔を隠さない。参照画面の多色HUDや装飾の量を本作へ一括で移さない。

### Spiritfarer：重なる情報と世界の絵をつなぐ

[Thunder Lotusの公式ギャラリー](https://thunderlotusgames.com/games/spiritfarer/) — [建築画面03](https://thunderlotusgames.com/wp-content/uploads/2023/10/Spiritfarer-SCREENSHOTS-03-576x324.jpg)・[場面08](https://thunderlotusgames.com/wp-content/uploads/2023/10/Spiritfarer-SCREENSHOTS-08-576x324.png)

**観察**：建築画面は船と海を広く残し、左の半透明の青緑の面に項目と素材をまとめる。金色の端飾りや細い区切りが同じ情報面の中で繰り返される。場面08では大きな亀と樹木が画面を占め、左の人物の近くに小さな吹き出しがある。海面への反射や手前の船も場面の大きさを伝える。画像だけから半透明面のぼかし方法や実装方式までは判断しない。

**採用**：情報面を開いても村が見える構成と、対象の近くに短い反応を置く関係を参考にする。枠の個性は同じ意味の部品で揃える。もぐの反応は表情・動作・短い状態表示で伝え、人語の会話へ変更しない。金の端飾りや青緑の面を複製するのではなく、器・湯気・村の案内から本作の図案を作る。

## ガラス材質の実装ガイド

[MicrosoftのAcrylic資料](https://learn.microsoft.com/en-us/windows/apps/design/style/acrylic)は、ゲームの美術資料とは分けて参照する。アプリ内の補助面や重なるナビゲーション、背景との視覚的なつながり、複数のガラス面を重ねないこと、文字の読みやすさ、単色への切り替えを扱う。WindowsのAcrylicをWebでそのまま再現する指定ではない。

`src/styles/field-ui.css` で、財布・小さな育成HUD・ナビなどに共通のガラス材質を適用する。純白の面 `#ffffffb3`（アルファ約70%）と `blur(18px)`、白い細線、無彩色の黒による柔らかい影を使い、村を背後に描く。海や屋根の色は背後の絵から透けて見えるものとし、ガラス自体へ薄い青・黄・紫を足さない。文字・数値・図案はぼかさず、赤い主操作には不透明な面と白文字を使う。ガラス面を入れ子にせず、隣り合う面のぼかしの継ぎ目も避ける。

通常・ダークテーマで同じ白い材質と紺黒の文字を使う。ぼかし非対応時は不透明な純白にし、`prefers-reduced-transparency: reduce` または `forced-colors: active` ではぼかしを止めて単色面に切り替える。強制配色時の最終表示色は利用者の配色設定に従う。透明効果の有無にかかわらず読めることを優先し、昼夜と明暗の違う背景を受入確認の対象にする。Acrylic資料のノイズや着色を一式採用せず、必要な材質表現だけを選ぶ。

## 本作の構成と共通規則

| 対象           | 採用する構成                                                                                                                                |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 村のフィールド | 画面全面に連続する空・海・建物・地面。背景を囲う窓枠を外し、遠景・中景・前景と接地の影で場所を作る。                                        |
| なかま         | 中央下の地面に置く。顔、身体、接地が分かる大きさを確保し、HUDと主操作で囲い込まない。                                                       |
| お客さん       | 最大3体をフィールドの地面に配置する。接地の影と小さな名前札を添え、身体を直接タップしてごはんをあげられる。                                 |
| 財布・育成     | 画面端の小さな情報群。共通の中立色Acrylicを使い、名前・数値・短いゲージを明快に読む。                                                       |
| 食事           | 大きな器を添えた赤い主操作。なかまとの対応を保ち、常設の広い情報帯から独立させる。                                                          |
| ナビゲーション | 財布・育成と同じ材質。ラベルは選択・hover時も紺黒のまま、選択中の案内図案と現在位置の印を赤にする。中にさらにガラスの選択カードを作らない。 |
| 詳細と反応     | 詳細は必要なときに開く。短い反応は対象に結び付け、主役の表情を隠さない。                                                                    |

白・黒の地は無彩色とし、純白へ微量の色味を加えない。村や料理、なかまの固有色と、UIの操作色・素材色は区別する。赤は主操作と現在位置の役割を保ち、すべての情報群を同じ強さで強調しない。

同じ役割の部品は同じ輪郭・材質・状態を使う。一般の角丸は四隅で揃え、一辺だけ太い線、強調目的の硬いオフセット影、理由のない角ごとの半径差を作らない。実際に世界の上へ浮くHUDやモーダルには、重なりを示す柔らかい影を使える。器や皿の円、札の対称な図案は対象の意味に基づいて使い分ける。

## 実装の対応

| 実装                                   | 受け持つ範囲                                                                                                                  |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `src/app/App.tsx`                      | 現在の画面を `data-page` で示し、財布と固定ナビを配置する。                                                                   |
| `src/features/room/RoomPage.tsx`       | `presentation="field"` の場面、中央のなかま、顔付きの育成HUD、器の食事ボタンを組み立てる。                                    |
| `src/ui/art/KayaScenery.tsx` と各背景  | いつものひろば、木もれび、星あかり、浜辺、小川、温室の6種類を描き分ける。                                                     |
| `src/ui/art/SceneryFrame.tsx`          | プレビューは既存の構図を保ち、フィールドは縦横比を測ってviewBoxを調整する。空・地面・前景を広げ、背景の外周に空白を作らない。 |
| `src/styles/field-ui.css`              | 全面ひろば、共通ガラスHUD、画面幅・高さに応じた配置、透明効果の代替表示。                                                     |
| `src/features/room/field-visitors.css` | お客さんのフィールド上の配置、接地、出現と待機中の動作、名前札。動きを抑える設定ではアニメーションを停止する。                |
| `src/app/styles.ts`                    | 既存テーマの後に `field-ui.css` を読み込み、表示規則の優先順を定める。                                                        |
| `tests/e2e/field-ui.spec.ts`           | 3画面サイズと6背景の全画面表示・操作領域、透明効果の代替表示、確認用画像の添付。                                              |

ひろばは `100svh` を基準に全面を使い、低い画面では568pxの最小高さを持つ。なかまの表示は成長段階と画面寸法に合わせて調整する。食事ボタンは育成HUDと同じ下側の領域に置き、固定ナビはその下に配置する。育成・食事・画面移動の既存の振る舞いを保つ。

## 受入条件

- ひろばを開くと村が画面全面に続き、外周の窓枠や常設の太い情報帯で区切られていない。
- なかまの顔・身体・接地と村の奥行きが見える。縦長画面でも食事ボタン・ナビ・育成HUDが重ならない。
- 財布・育成・ナビのガラス材質、文字、境界、選択表示が揃い、ガラス面が二重になっていない。
- 食事の器と赤い主操作が見つけやすく、補助操作や報酬の図案が同じ強さで競合しない。
- 明るい空、暗い屋根、夜景が背後に来ても数値とラベルが読める。不透明な純白への切り替えでも同じ操作ができる。
- キーボードのフォーカス、操作領域、動きを抑える設定、シートや通知の重なりを確認する。装飾の背景が操作を妨げない。
- 食事、育成表示、財布の更新、画面移動、詳細の開閉が既存どおり動く。スクリーンショット確認と必要な動作テストで確かめる。

## 検証（2026-09-25）

- Chromiumの390×844、320×568、1440×900で6背景を確認。全面表示、横方向のはみ出し、食事・なかま・ナビの操作領域をE2Eで検査した。
- 透明効果を抑える設定では財布・育成・ナビが純白へ切り替わり、操作を維持することを確認した。
- 長いなかま名、成長後の姿、お客さんが3匹いる320px画面も確認。名前は表示だけを省略し、読み上げる名前と今日の食事状態を保持する。
- `field-ui.spec.ts` の5件、既存の `play-guide.spec.ts` の4件、`accessibility.spec.ts` の5件が成功。食事、育成、ずかん・おみせへの移動、あそびかたガイドの復帰とフォーカスを含む。
- TypeScriptを含むproduction build、Lint、対象ファイルの整形を確認した。背景の継ぎ目と操作の重なりは生成した画面画像でも確認した。

ブラウザの自動検証と画面画像の確認であり、実機ごとのGPU負荷やSafariの描画性能測定は含まない。
