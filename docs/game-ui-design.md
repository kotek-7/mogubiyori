# 料理となかまが主役の育成ゲーム — UIデザイン仕様

毎日の料理が、なかまの成長と新しい出会いにつながる。画面の中心には料理となかまを置き、操作や数値はその体験を支える位置にまとめる。ひろば、食事、図鑑を通して、カヤ村で遊び続けていると感じられるデザインにする。

プレイヤーは自分の料理を記録して、ひろばの生き物を育てる。こむぎたちは人語で話さず、表情と動作で反応する。操作・状態・結果はシステムが表示する。手順説明は初回と、ユーザーが開いた「あそびかた」にまとめる。文言の責務と文字量は[UI文言ガイド](ui-writing.md)に従う。

## カヤ村の色と形

[世界設定](world.md)の「下のかまど」を美術の中心にする。海に面した土の庭、赤茶の瓦、雨戸、低い棚に並ぶ器を、大きな色面と材質に合った描線で描く。絵の色、形、構図でポップな印象を作り、なかまと料理が背景から見分けられるようにする。

画面全体は暖灰の地、器白の紙面、焦茶のインクで統一する。主操作は朱、報酬は金、成長や完了の進捗は緑を使う。海や植物、土壁の色は場面や道具の絵に置き、画面ごとに新しい操作色へ割り当てない。土色を全画面の地へ広げず、料理やなかまの鮮やかさを受け止める余白を残す。

器と湯気の紋、かまど・本・市場の案内記号、麦・波・器の背景画を、同じ世界の図案として繰り返す。個性は共通の図案に持たせ、同じ役割の部品は同じ輪郭・配色・状態を使う。四隅で理由なく半径を変える、画面固有のボタンを作る、意味のない点・斜線・英語ラベルを足す、といった装飾は行わない。

## 共通パターンと操作状態

ひろば、Journey、図鑑、ショップ、ダイアログは次の部品を再利用する。同じ役割なら、画面の雰囲気に合わせて色・輪郭・影を作り直さない。

| パターン           | 輪郭と面                                                                            | 共通の使い方                                                                                                                            |
| ------------------ | ----------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| **主操作の札**     | `action-frame.svg` の朱の面、器白の文字、細い内枠。四隅は同じ曲線の切り欠きで対称。 | 給餌、次へ、確定など。一画面の主要な操作に使い、Journeyでも同じ形と色を保つ。SVGを9分割して描き、幅が変わっても角と枠の形を伸ばさない。 |
| **白い札**         | `paper-frame.svg` の器白の面。主操作と同じ対称な輪郭と細い内枠。                    | ナビゲーションの外枠。同じ図案の白面として使い、画面ごとに別の切り欠きを作らない。                                                      |
| **二次操作・入力** | 四隅が均一な12pxの角丸。器白の面、焦茶の文字、共通の境界と影。                      | 戻る、変更、検索、設定の選択肢。大きさが違っても状態と輪郭の規則は共通。                                                                |
| **記録紙面**       | 四隅が均一な8pxの角丸、器白の面、細い内枠と罫線。                                   | 料理カード、図鑑、履歴、プロフィール、ダイアログ内の記録。内容は見出しと区切りで整理し、小さな情報ごとに枠を増やさない。                |
| **場面**           | 四隅が均一な24pxの角丸。絵と接続する情報面を一つのまとまりにする。                  | ひろば、写真、食卓。接続する領域は接合側の角丸だけを0にして隙間なくつなぎ、外周の規則を保つ。                                           |
| **対象固有の円**   | 円形。                                                                              | 皿、丸いバッジ、44pxの単独アイコン操作。閉じる・通知などのアイコン操作はこの形を全画面で共有する。                                      |

形の定義は共有トークンと共通SVGに置く。各画面で四隅の半径、切り欠き、色、影を直書きして例外を足さない。器やかまどの形は背景・道具の絵に表し、同じ操作を画面ごとにアーチ、丸、札へ変えない。

- **通常・hover・押下**：同じ種類の操作は同じ色変化と短い押下反応を使う。朱の主操作は濃い朱へ変化させる。
- **選択中**：`--game-action-soft` の面と `--game-action` の輪郭を共通にし、既存のチェックや下線を併用する。なかま選択、タブ、設定で別の選択色を作らない。
- **無効・フォーカス**：無効は共通の控えめな面と文字で示し、操作可否も一致させる。キーボードフォーカスは選択状態と別に見える輪郭を保つ。
- **進捗・報酬**：成長や完了は `--game-success`、コインや獲得は `--game-gold`。主操作の色とは役割を分ける。

## 背景と道具の図案

`VillageBackdrop` は麦、波、器を画面の端に配置した共通の背景画とする。描いたSVGを使い、意味のないCSSの点や斜線を重ねない。文字や入力の背後は静かに保ち、場面ごとに異なる背景模様を増やさない。

食卓の `table-linen.svg` も同じ波と穂を縁の図案に使う。料理の近くには広い無地の面を残す。`KayaScenery` は、器・かまどの近景、家や土壁の中景、海と島影の遠景を、材質と距離に応じた描線・彩度で分ける。共通のインクと場面の配色に接続しながら、すべての物体を同じ太線で囲わない。

## ひろばの構成

視線は「なかまのいる場面 → 今日の状態 → ごはんをあげる → ほかの場所へ」の順に流れる。

1. **HUD**：上部には器と湯気の紋、ゲーム名、所持数を小さくまとめる。財布は静かな面と短い表示にし、長い説明や宣伝見出しを置かない。
2. **プレイフィールド**：カヤ村の下のかまどを一つの場面として見せ、中央のなかまを主役にする。海、屋根、器、庭は大きな形で描き、訪問者や料理を周囲に置く。空腹・満腹などは短い状態ラベルで示す。
3. **育成状態と主操作**：場面の下に器白の紙面を接続し、名前、緑の成長ゲージ、朱の給餌ボタンをまとめる。本文は焦茶で表示し、主操作の文字は器白にする。誰に何をするかが一目で分かる配置にする。
4. **下部ナビゲーション**：白い札の中に、かまど、本、市場の絵と短いラベルを置く。選択は共通の淡い朱の面・朱の輪郭と印で示す。画面下の安全領域を確保し、本文や主操作に重ねない。

通常・庭・夜の背景は同じカヤ村の場所として描き分ける。背景の着せ替え条件とゲーム上の効果は美術変更と独立させる。ひろば固有の配色や角丸を操作へ持ち込まず、共通パターンを使う。

## 食事のJourney

食事は一つの画面にフォームと結果を詰め込まず、料理となかまに順に目が向く流れにする。

**写真を選ぶ・写真なしで体験する → 食卓で料理を確認する → ごはんをあげる → 食事と今回の出来事を見る → ひろばへ戻る**

- 写真選択と料理確認は短い進捗表示で位置を示す。戻る・閉じる操作を主操作から分離する。
- 各画面の見出しは目的または結果を一つ示す。主操作と同じ意味の副題や、なかまの発言に見えるキャプションを重ねない。
- 出会いの選択面は共通の紙面と選択状態、写真は共通の場面枠、食卓は波と穂の縁を持つ布で構成する。主役の絵と道具の表現を変えても、操作部品の規則は変えない。
- 写真は傾けず、大きなプレビューとして扱う。入力欄や補足は料理を囲む位置にまとめ、模様の上に本文を重ねない。
- Journeyの主操作は、ひろばと同じ朱の札と器白の文字を使う。戻る・変更は共通の二次操作とする。手順の現在位置は朱、成長の進捗は緑、報酬は金で示す。
- 食事中と食後はなかまの姿を中心にする。成長、仲間入り、カード獲得、来訪、継続の贈り物は、今回発生した出来事だけを順に見せる。
- 経験値・コイン・継続日数は共通の報酬パネルにまとめる。数値ごとの大きなカードを増やして、なかまの反応より目立たせない。
- 食事演出には早送りを用意し、結果の進行や「ひろばへ」を見つけやすくする。演出を見続けることを操作完了の条件にしない。

## 図鑑の構成と情報密度

本体のコレクションは共通の記録紙面にまとめ、種類の切り替えは共通の選択色と下線を使ったタブで示す。料理カードの枠と、一覧を整理する罫線を描き分ける。名前、絵、収集状態を優先し、長い説明は詳細で読む。

拡張図鑑は、大量の料理カード・なかま・アイテムを同じ世界の中で探せる画面にする。上部は「ひろばへ」「図鑑」「件数」を短く並べ、その下に種類のタブ、検索と絞り込み、一覧を置く。

- タブは「料理カード」「なかまたち」「きせかえとひろば」。アイコン、文字、件数を組み合わせ、選択状態を色だけで伝えない。
- 料理カードは、料理の絵、名前、分類、時間などの短い情報を優先する。材料・手順・長い説明は詳細で読む。カード全体を開く操作にし、同じ大きな「開く」ボタンを各カードへ繰り返さない。
- 一覧は広い画面で4列、中間幅で3列、狭い画面で2列。料理名の折り返しと画像の見分けやすさを守る。カードの説明量を増やして列幅の不足を埋めない。
- 24件ずつ表示し、検索、分類、所要時間、難易度、並び順から絞り込む。結果件数、該当なし、条件を戻す操作を一覧の近くに置く。
- 詳細は画像と説明を一つのダイアログで見せる。キーボードで閉じられ、閉じる操作と題名が分かる構造を維持する。
- 収録内容の説明は図鑑下部にまとめる。実際の解放状況と、拡張用に用意されたカタログの収録件数を混同させない。

## 文字と操作の読みやすさ

画面の見出しと主操作は各一つに絞り、説明は意味が必要なときだけ置く。ラベルには句点を付けず、本文では自然な句読点を保つ。装飾的な読点、余韻を作る文言、説明のない英語ラベルは用いない。具体例と図鑑・設定の文言の責務は[UI文言ガイド](ui-writing.md)を参照する。

明るい面では本文を焦茶、補足を濃い暖灰で表示し、朱の主操作では器白の文字を使う。文字を薄くして階層を作らず、大きさ、太さ、余白でも差を伝える。長い本文は画像や模様へ直接重ねず、無地の面を用意する。装飾書体の印象だけに頼らず、日本語の名前と本文を読みやすく保つ。

採用色同士のコントラスト比は、本文と器白の面が約13.05:1、補足と器白の面が約5.62:1、器白の文字と朱の主操作が約4.85:1、焦茶と金が約6.21:1。これらを通常の文字と操作ラベルの基本の組み合わせとする。値は上表の単色同士からの計算であり、画像や半透明色を含む個々の画面全体の検査結果ではない。

通知やエラーはアイコンと文言を併用し、色だけで状態を伝えない。金の面には焦茶の文字を使う。淡い選択面や進捗の下地を本文の文字色に使わない。

- モバイルの操作領域は44×44px以上を基準とする。小さなアイコンでも当たり領域は確保し、画面幅が狭い場合も縮めない。
- ボタン、リンク、入力欄には見えるフォーカスを残す。選択中、未選択、無効の状態を、色に加えて形・文字・操作可否で区別する。
- 検索や絞り込みには名前を付け、結果件数の変化を支援技術へ伝える。装飾アイコンを読み上げ文へ重複させない。
- なかまの動きと短い押下反応は楽しさを補助する。`prefers-reduced-motion` ではアニメーションとトランジションを止め、スクロールも即時にする。動きがなくても進行と結果が分かる構造を保つ。

本体も `index.html` から共有トークンを読み込む。機能ごとのCSSは `src/features/<機能>/`、共通の画面枠は `src/ui/journey/` に置く。`src/app/styles.ts` から順番を明示して読み込み、ファイルの配置やrouteの読み込み時期で既存のcascadeを変えない。

機能ごとのCSSは配置と進行を受け持ち、色・角・影・選択状態は共有トークンと本体・Journeyのテーマへ集約する。別のテーマファイルや画面専用の上書きを重ねない。

新しい画面や操作を追加するときは、主操作の札、二次操作、記録紙面、場面のどれに当たるかを決め、既存の通常・hover・押下・無効・フォーカス・選択の規則を再利用する。追加内容の個性は料理、なかま、村の絵で表し、操作の手掛かりは同じ言葉と形で保つ。
