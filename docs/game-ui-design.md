# 料理となかまが主役の育成ゲーム — UIデザイン仕様

毎日の料理が、なかまの成長と新しい出会いにつながる。画面の中心には料理となかまを置き、操作や数値はその体験を支える位置にまとめる。ひろば、食事、図鑑を通して、カヤ村で遊び続けていると感じられるデザインにする。

プレイヤーは自分の料理を記録して、ひろばの生き物を育てる。こむぎたちは人語で話さず、表情と動作で反応する。操作・状態・結果はシステムが表示する。手順説明は初回と、ユーザーが開いた「あそびかた」にまとめる。文言の責務と文字量は[UI文言ガイド](ui-writing.md)に従う。

## カヤ村の色と形

[世界設定](world.md)の「下のかまど」を美術の中心にする。海に面した土の庭、赤茶の瓦、雨戸、低い棚に並ぶ器を、大きな色面と材質に合った描線で描く。絵の色、形、構図でポップな印象を作り、なかまと料理が背景から見分けられるようにする。

任天堂のゲームUIで見られる、明快な面の強弱、現在位置の印、短く太い操作ラベルを参考にする。ひろばは全面の村に中立色のガラスHUDを重ね、紺黒の文字と赤い主操作を焦点に置く。図鑑などの記録は白い紙面で読む。黄色はコインや報酬の小さな絵に使う。色数を目標にせず、それぞれの色が何を示し、どの面積を占めるかを揃える。料理となかまは固有色を保ち、海や植物、土壁の背景は彩度を抑えて主役を支える。

器と湯気の紋、かまど・本・市場の案内記号、麦・波・器の背景画を、同じ世界の図案として繰り返す。個性は共通の図案に持たせ、同じ役割の部品は同じ輪郭・配色・状態を使う。四隅で理由なく半径を変える、画面固有のボタンを作る、意味のない点・斜線・英語ラベルを足す、といった装飾は行わない。

## 採用パレットと色の役割

色値の出発点は、ENDESGAが制作しLospecで公開されている[ENDESGA 8パレット](https://lospec.com/palette-list/endesga-8)。紺黒・赤と小さな報酬の黄色を採用し、白は用途を優先して掲載値から純白 `#FFFFFF` に調整する。白い最背面や紙面に微量の色味を加えず、白・黒の地は無彩色にする。役割と使用範囲は本作で定める。パレットの色数を制限として扱わない。ゲーム本体と拡張図鑑の定義元は `public/game-tokens.css`。

| トークン         | 採用色    | UIでの役割                                                   |
| ---------------- | --------- | ------------------------------------------------------------ |
| `--game-surface` | `#FFFFFF` | 紙面、入力、白い札、赤い主操作上の文字。                     |
| `--game-ink`     | `#1B1C33` | 本文、見出し、記号、主要な輪郭、進捗や状態の表示。           |
| `--game-action`  | `#D32734` | 全画面共通の主操作と現在位置・選択の印。                     |
| `--game-gold`    | `#E6DA29` | コイン・報酬の小さな絵。本文や大きなパネルの色には広げない。 |

最背面の `--game-canvas` と紙面の `--game-surface` は純白にする。補足文字、境界、無効状態には、無彩色の `--game-neutral: #202020` と純白を混ぜた中立階調を使う。淡い面は無彩色6%、補足文字は72%、境界は18%、強い境界は48%とし、紺黒の色味を混ぜない。ひろばの育成HUDは純白を基にしたガラス面と紺黒の文字・ゲージを使う。ガラスの透け具合と代替表示は[全面フィールドUI](immersive-field-ui.md)に定める。派生値は共有トークンに置く。小さな赤文字には赤90%と紺黒10%を混ぜた `--game-action-dark` を使い、灰色の面での読みやすさを確保する。既存の色名を含むトークン名ではなく、現在の表示上の役割に従う。

広い紙面は白、ひろばの情報を支える面は中立色のガラス、文字は紺黒、操作の焦点は赤い面または印にする。黄色の報酬は小さく添える。新しい色が必要な場合は、用途・面積・他の強調との優先順位を定める。同じパレットに属することだけを理由に色を広げない。明暗差と面積で階層を作り、すべての情報枠へ同じ強さのアクセントを配らない。

料理・なかま・背景の絵はUIの色指定と区別する。料理やなかまの固有色は残し、背景の彩度は抑えたまま、近景と遠景の明度で奥行きを作る。素材の色をそのままボタンや状態ラベルの色へ持ち込まない。任天堂の参照画面は面の構成・選択表示・文字の強弱の根拠、上記パレットは色値の出発点とする。任天堂作品の公式色を採用したという意味ではない。

## 共通パターンと操作状態

ひろば、Journey、図鑑、ショップ、ダイアログは次の部品を再利用する。同じ役割なら、画面の雰囲気に合わせて色・輪郭・操作状態を作り直さない。

| パターン             | 輪郭と面                                                                                          | 共通の使い方                                                                                                                                      |
| -------------------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| **主操作**           | 赤い不透明な面と白い文字。Journeyなどの札は `action-frame.svg` の対称な切り欠きと細い内枠を使う。 | 給餌、次へ、確定。札型はSVGを9分割して角の形を保つ。ひろばの給餌は器を大きく添えた均一な角丸の操作面としてHUDに並べ、赤と白文字の役割を共有する。 |

通常の情報枠は平面として扱い、境界が必要な箇所を均等な1pxの線で区切る。カードの厚みを表す一辺だけ厚いボーダー、硬いオフセット影、hoverで持ち上がるカードを強調に使わない。汎用パネルには二重枠を重ねず、内枠は描いた札のSVGや、実物の収集カード・吹き出しなど対象の表現に意味がある箇所へ限る。情報を整理する罫線や、カテゴリの共通ベースライン上で現在位置を示す下線は、立体感を作るための太い一辺と区別する。

影は重なりと距離を伝える。本文の上に浮く固定ナビやモーダルには、薄く拡散したドロップシャドウを使える。選択中や重要な情報であることだけを理由に影を付けない。ナビの外枠が浮いていても、中のアイコン・文字・選択表示は一つの平面に置く。

形の定義は共有トークン、共通SVG、役割を受け持つ共通部品のCSSに置く。HUDの形と材質は `field-ui.css` に集約する。各画面で四隅の半径、切り欠き、色、影を直書きして例外を足さない。器やかまどの図案と、文字や情報を支える面を描き分ける。

- **通常・hover・押下**：同じ種類の操作は同じ文字・面・境界の色変化を使う。主操作の赤と白文字を保ち、境界などの共通表現で反応を示す。通常のボタンや一覧を移動・拡縮して浮き沈みさせない。
- **選択項目**：なかまや設定などの選択肢は、`--game-action` の均等な細枠と既存のチェックを使う。背景は白または中立階調にし、影や一辺の太さで選択を示さない。
- **固定ナビ**：一枚のガラス面の中で、項目の背景は透明にする。ラベルは選択・hover時も紺黒のまま、現在位置を赤い案内記号と小さな印で示す。選択アイコンだけを2px上げて現在位置を補う。
- **拡張図鑑のタブ**：透明な背景に赤のラベルとラベル左の小さな点で現在位置を示す。単色アイコンはラベルに色を揃え、件数も同じ平面に置く。
- **ページ内カテゴリ**：本体の図鑑・ショップは透明なタブを共通のベースラインに並べ、現在位置を赤のラベルと下線で示す。タブ項目に面や角丸を付けない。どちらのタブも選択項目を別のカードとして囲まず、塗りつぶしや硬い下影を足さない。
- **無効・フォーカス**：無効は共通の控えめな面と文字で示し、操作可否も一致させる。キーボードフォーカスは選択状態と別に見える輪郭を保つ。
- **進捗・報酬**：進捗は白・紺黒と中立階調のゲージ、完了や獲得は記号・数値・文言で示す。コインや報酬の小さな絵には黄色を使い、周囲のパネルや本文まで黄色にしない。主操作と現在位置の赤に対し、報酬の色面積を小さく保つ。

## 背景と道具の図案

図鑑やショップの `VillageBackdrop` は麦、波、器を画面の端に配置した共通の背景画とする。ひろばではこれを隠し、6種類のフィールドを全面に描く。描いたSVGを使い、意味のないCSSの点や斜線を重ねない。文字や入力の背後は静かに保ち、場面ごとに異なる背景模様を増やさない。

食卓の `table-linen.svg` も同じ波と穂を縁の図案に使う。料理の近くには広い無地の面を残す。`KayaScenery` は、器・かまどの近景、家や土壁の中景、海と島影の遠景を、材質と距離に応じた描線・彩度で分ける。共通のインクと場面の配色に接続しながら、すべての物体を同じ太線で囲わない。

## ひろばの構成

視線は「なかまのいる場面 → 今日の状態 → ごはんをあげる → ほかの場所へ」の順に流れる。

1. **HUD**：上部に器と湯気の紋、財布、設定を小さくまとめる。財布は共通のガラス面に数値と道具を置き、村がその下まで続くようにする。
2. **プレイフィールド**：外周の枠や角丸を設けず、村を画面全面に描く。`SceneryFrame` の `field` 表示が縦横比に合わせて空・地面・前景を広げ、中央下のなかまを見せる。空腹・満腹などは端の短い状態表示にまとめる。
3. **育成状態と主操作**：画面下側に、小さな育成HUDと大きな器を添えた赤い給餌ボタンを分けて置く。育成は顔・名前・紺黒のゲージをガラス面で読み、給餌は不透明な赤と白文字で示す。背後の村と中央のなかまを見えるままにする。
4. **下部ナビゲーション**：一枚のガラス面に、かまど、本、市場の絵と短いラベルを置く。ラベルは常に紺黒、選択アイコンと現在位置の印は赤にする。給餌ボタンの下に置き、画面下の安全領域を確保する。

構図の根拠、ガラス材質、代替表示、実装対応と受入条件は[全面フィールドUI](immersive-field-ui.md)にまとめる。

背景はカヤ村とその周辺の6か所を描き分ける。いつものひろばは海を望むかまどの庭、木もれびのひろばは大きな木の天蓋と光の落ちる空き地、星あかりのひろばは夜の庭、夕なぎの浜辺は夕日と砂浜、小川のほとりはせせらぎと木の橋、温室のひろばはガラス屋根と鉢植えで構成する。色替えや端の小物だけに頼らず、商品画像と縦長画面の中央にも各場所の特徴を残す。なかまの立つ中央手前は見やすく保つ。背景の着せ替え条件とゲーム上の効果は美術変更と独立させる。ひろば固有の配色や角丸を操作へ持ち込まず、共通パターンを使う。

## 食事のJourney

食事は一つの画面にフォームと結果を詰め込まず、料理となかまに順に目が向く流れにする。

**写真を選ぶ・写真なしで体験する → 食卓で料理を確認する → ごはんをあげる → 食事と今回の出来事を見る → ひろばへ戻る**

- 写真選択と料理確認は短い進捗表示で位置を示す。戻る・閉じる操作を主操作から分離する。
- 各画面の見出しは目的または結果を一つ示す。主操作と同じ意味の副題や、なかまの発言に見えるキャプションを重ねない。
- 出会いの選択面は共通の紙面と選択状態、写真は共通の場面枠、食卓は波と穂の縁を持つ布で構成する。主役の絵と道具の表現を変えても、操作部品の規則は変えない。
- 写真は傾けず、大きなプレビューとして扱う。入力欄や補足は料理を囲む位置にまとめ、模様の上に本文を重ねない。
- Journeyの主操作は赤い札と白い文字を使い、ひろばの食事ボタンと操作色の役割を共有する。戻る・変更は共通の二次操作とする。手順の現在位置は赤、成長の進捗は白・紺黒の記号・数値・ゲージで示す。報酬の黄色は小さな絵に使う。
- 食事中と食後はなかまの姿を中心にする。成長、仲間入り、カード獲得、来訪、継続の贈り物は、今回発生した出来事だけを順に見せる。
- 経験値・コイン・継続日数は共通の報酬パネルにまとめる。数値ごとの大きなカードを増やして、なかまの反応より目立たせない。
- 食事演出には早送りを用意し、結果の進行や「ひろばへ」を見つけやすくする。演出を見続けることを操作完了の条件にしない。

## 図鑑の構成と情報密度

図鑑とおみせの見出し右には共通の64pxの `VillageSign` を置き、ページの対象を絵でも示す。

本体の図鑑とアルバムは、外周の枠・角丸がない白い記録紙面にまとめる。種類の切り替えは透明なタブを共通のベースラインに並べ、赤と下線で現在位置を示す。料理カードの枠と、一覧を整理する罫線を描き分ける。名前、絵、収集状態を優先し、長い説明は詳細で読む。

拡張図鑑は、大量の料理カード・なかま・アイテムを同じ世界の中で探せる画面にする。上部は「ひろばへ」「図鑑」「件数」を短く並べ、その下に種類のタブ、検索と絞り込み、一覧を置く。

- タブは「料理カード」「なかまたち」「きせかえとひろば」。アイコン、文字、件数を組み合わせ、選択状態を色だけで伝えない。
- 料理カードは、料理の絵、名前、分類、時間などの短い情報を優先する。材料・手順・長い説明は詳細で読む。一覧の枠は均等な細線にし、影やhoverの浮上を付けない。カード全体を開く操作にし、同じ大きな「開く」ボタンを各カードへ繰り返さない。
- 一覧は広い画面で4列、中間幅で3列、狭い画面で2列。料理名の折り返しと画像の見分けやすさを守る。カードの説明量を増やして列幅の不足を埋めない。
- 24件ずつ表示し、検索、分類、所要時間、難易度、並び順から絞り込む。結果件数、該当なし、条件を戻す操作を一覧の近くに置く。
- 詳細は画像と説明を一つのダイアログで見せる。キーボードで閉じられ、閉じる操作と題名が分かる構造を維持する。
- 収録内容の説明は図鑑下部にまとめる。実際の解放状況と、拡張用に用意されたカタログの収録件数を混同させない。

## 文字と操作の読みやすさ

画面の見出しと主操作は各一つに絞り、説明は意味が必要なときだけ置く。ラベルには句点を付けず、本文では自然な句読点を保つ。装飾的な読点、余韻を作る文言、説明のない英語ラベルは用いない。具体例と図鑑・設定の文言の責務は[UI文言ガイド](ui-writing.md)を参照する。

白い面では本文を紺黒、補足を純白と無彩色の灰から作った濃い中立階調で表示し、赤い主操作では白い文字を使う。文字を薄くして階層を作らず、大きさ、太さ、余白でも差を伝える。長い本文は画像や模様へ直接重ねず、無地の面を用意する。主要操作と名前は短く太い文字で見せ、補助説明は大きさと余白で一段下げる。装飾書体の印象だけに頼らず、日本語の名前と本文を読みやすく保つ。

採用色同士のコントラスト比は、白と紺黒が約16.66:1、白と赤が約5.11:1。本文は紺黒地に白または白地に紺黒、主操作は赤地に白を使う。赤と紺黒は約3.26:1で通常の小さな文字には不足するため、紺黒の面に赤い文字を置かない。暗い面のラベルは白で表示する。値は上表の単色同士からの計算であり、混色・画像・半透明色を含む個々の画面全体の検査結果ではない。

通知やエラーはアイコンと文言を併用し、色だけで状態を伝えない。状態の違いを新しい色相だけで示さず、形と短い状態名を併用する。淡い境界や進捗の下地を本文の文字色に使わない。

- モバイルの操作領域は44×44px以上を基準とする。小さなアイコンでも当たり領域は確保し、画面幅が狭い場合も縮めない。
- ボタン、リンク、入力欄には見えるフォーカスを残す。選択中、未選択、無効の状態を、色に加えて形・文字・操作可否で区別する。
- 検索や絞り込みには名前を付け、結果件数の変化を支援技術へ伝える。装飾アイコンを読み上げ文へ重複させない。
- なかまの動きは楽しさを、操作の控えめな色変化は状態の理解を補助する。食事ボタンではhover時に器の絵だけを小さく傾け、ボタン全体を浮かせない。`prefers-reduced-motion` ではアニメーションとトランジションを止め、スクロールも即時にする。動きがなくても進行と結果が分かる構造を保つ。

本体も `index.html` から共有トークンを読み込む。機能ごとのCSSは `src/features/<機能>/`、共通の画面枠は `src/ui/journey/` に置く。`src/app/styles.ts` から順番を明示して読み込み、ファイルの配置やrouteの読み込み時期で既存のcascadeを変えない。

機能ごとのCSSは配置と進行を受け持ち、基本の色・角・線・選択状態は共有トークンと本体・Journeyのテーマへ集約する。全面フィールドと共通ガラスHUDは `field-ui.css` が受け持ち、既存テーマの後に読み込む。同じ役割の定義を各ページへ重複させず、部品を受け持つファイルで更新する。

新しい画面や操作を追加するときは、主操作、ガラスHUD、二次操作、記録紙面、カード・情報枠、場面のどれに当たるかを決め、既存の通常・hover・押下・無効・フォーカス・選択の規則を再利用する。追加内容の個性は料理、なかま、村の絵で表し、操作の手掛かりは同じ言葉と形で保つ。
