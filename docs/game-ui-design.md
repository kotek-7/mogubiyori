# 料理となかまが主役の育成ゲーム — UIデザイン仕様

毎日の料理が、なかまの成長と新しい出会いにつながる。画面の中心には料理となかまを置き、操作や数値はその体験を支える位置にまとめる。ひろば、食事、図鑑を通して、同じ世界で遊び続けていると感じられるデザインにする。

プレイヤーは自分の料理を記録して、ひろばの生き物を育てる。こむぎたちは人語で話さず、表情と動作で反応する。操作・状態・結果はシステムが表示する。手順説明は初回と、ユーザーが開いた「あそびかた」にまとめる。文言の責務と文字量は[UI文言ガイド](ui-writing.md)に従う。

### 面積の配分

料理、なかま、背景のイラストを除いたUI面では、明るい地と白い面をおおむね70〜80%、ティール系の選択・操作面を10〜20%、ゴールド・コーラルなどの強いアクセントを合わせて10%以下に収めることを目安とする。この比率は設計上の目安であり、画面からの実測値ではない。

ゴールドの大きなボタンは画面内の主操作一つに絞る。コーラルは小さな点やハートなどに使い、カードごとに別の色を割り当てない。青と紫は意味のある状態表示に限定する。料理の自然な色やなかまの個性はこの面積配分の対象に含めず、UIの配色に合わせて一律に薄くしない。

## ひろばの構成

視線は「なかまのいる場面 → 今日の状態 → ごはんをあげる → ほかの場所へ」の順に流れる。

1. **HUD**：上部にはゲーム名と所持数を小さくまとめる。数値は白いカプセルに載せ、アイコンと単位で用途を識別する。長い説明や大きな宣伝見出しは置かない。
2. **プレイフィールド**：ひろばを一つの場面として見せ、中央のなかまを最大の主役にする。訪問者や料理は周囲に置き、背景の鮮やかさを維持する。なかまは表情と動作で反応し、空腹・満腹などは短い状態ラベルで示す。
3. **育成状態と主操作**：名前と成長ゲージを給餌ボタンに近づけ、誰に何をするかを一目で分かるようにする。主操作はゴールドと濃紺文字。報酬や条件の補足は、操作の判断に必要なものだけ添える。
4. **下部ナビゲーション**：白い一つの帯にアイコンと短いラベルを並べる。選択中は淡いティールの面と濃いティールの文字で表す。画面下の安全領域を確保し、本文や主操作に重ねない。

カードやパネルは20px前後の角丸、操作は16px前後の角丸を基本にする。細い境界と短い影で押せる面を伝え、押下時にはわずかに沈む。大きな影、傾いた紙、過剰な装飾を全要素へ反復しない。

## 食事のJourney

食事は一つの画面にフォームと結果を詰め込まず、料理となかまに順に目が向く流れにする。

**写真を選ぶ・写真なしで体験する → 食卓で料理を確認する → ごはんをあげる → 食事と今回の出来事を見る → ひろばへ戻る**

- 写真選択と料理確認は短い進捗表示で位置を示す。戻る・閉じる操作を主操作から分離する。
- 各画面の見出しは目的または結果を一つ示す。主操作と同じ意味の副題や、なかまの発言に見えるキャプションを重ねない。
- 写真は傾けず、明るい一枚の面として大きく扱う。入力欄や補足は料理を囲む位置にまとめる。
- Journeyの主操作はゴールド、戻る・変更などの補助操作は白い面とティール文字に統一する。一画面の大きな主操作は一つ。
- 食事中と食後はなかまの姿を中心にする。成長、仲間入り、カード獲得、来訪、継続の贈り物は、今回発生した出来事だけを順に見せる。
- 経験値・コイン・継続日数は共通の報酬パネルにまとめる。数値ごとの大きなカードを増やして、なかまの反応より目立たせない。
- 食事演出には早送りを用意し、結果の進行や「ひろばへ」を見つけやすくする。演出を見続けることを操作完了の条件にしない。

## 図鑑の構成と情報密度

拡張図鑑は、大量の料理カード・なかま・アイテムを同じ世界の中で探せる画面にする。上部は「ひろばへ」「図鑑」「件数」を短く並べ、その下に種類のタブ、検索と絞り込み、一覧を置く。

- タブは「料理カード」「なかまたち」「きせかえとひろば」。アイコン、文字、件数を組み合わせ、選択状態を色だけで伝えない。
- 料理カードは、料理の絵、名前、分類、時間などの短い情報を優先する。材料・手順・長い説明は詳細で読む。カード全体を開く操作にし、同じ大きな「開く」ボタンを各カードへ繰り返さない。
- 一覧は広い画面で4列、中間幅で3列、狭い画面で2列。料理名の折り返しと画像の見分けやすさを守る。カードの説明量を増やして列幅の不足を埋めない。
- 24件ずつ表示し、検索、分類、所要時間、難易度、並び順から絞り込む。結果件数、該当なし、条件を戻す操作を一覧の近くに置く。
- 詳細は画像と説明を一つのダイアログで見せる。キーボードで閉じられ、閉じる操作と題名が分かる構造を維持する。
- 収録内容の説明は図鑑下部にまとめる。実際の解放状況と、拡張用に用意されたカタログの収録件数を混同させない。

## 文字と操作の読みやすさ

画面の見出しと主操作は各一つに絞り、説明は意味が必要なときだけ置く。ラベルには句点を付けず、本文では自然な句読点を保つ。装飾的な読点や余韻を作る文言は用いない。具体例と図鑑・設定の文言の責務は[UI文言ガイド](ui-writing.md)を参照する。

本文は濃紺、補足は青みのある濃いグレーを基本とし、文字を薄くして階層を作らない。見出し・本文・補足の差は大きさ、太さ、余白でも伝える。画像の上に長い本文を直接重ねず、白い面を用意する。

採用色同士のコントラスト比は、本文と白い面が約11.39:1、補足と白い面が約5.83:1、白い文字とティールが約4.81:1、濃紺文字とゴールドが約6.34:1。これらを通常の文字と操作ラベルの基本の組み合わせとする。値は単色同士からの計算であり、個々の画面全体の検査結果ではない。

コーラルと白い面は約3.63:1のため、小さな本文の色には使わない。通知やエラーはアイコン、文言、必要に応じた濃い文字を併用する。ゴールドのボタンに白文字を載せない。

- モバイルの操作領域は44×44px以上を基準とする。小さなアイコンでも当たり領域は確保し、画面幅が狭い場合も縮めない。
- ボタン、リンク、入力欄には見えるフォーカスを残す。選択中、未選択、無効の状態を、色に加えて形・文字・操作可否で区別する。
- 検索や絞り込みには名前を付け、結果件数の変化を支援技術へ伝える。装飾アイコンを読み上げ文へ重複させない。
- なかまの動きと短い押下反応は楽しさを補助する。`prefers-reduced-motion` ではアニメーションとトランジションを止め、スクロールも即時にする。動きがなくても進行と結果が分かる構造を保つ。

## 実装の対応

| 実装                                         | 受け持つ範囲                                                                        |
| -------------------------------------------- | ----------------------------------------------------------------------------------- |
| `public/game-tokens.css`                     | 本体と図鑑で共有する色、角丸、影。採用パレットの定義元。                            |
| `src/game-theme.css`                         | 本体のHUD、ひろば、主操作、下部ナビゲーション、コレクション、ショップ、ダイアログ。 |
| `src/journey-theme.css`                      | 出会い・写真選択・料理確認・食事・成果表示のJourneyを同じテーマに揃える。           |
| `public/expansion/index.html`                | 図鑑のヘッダー、タブ、検索、一覧、詳細の構造。共有トークンを読み込む。              |
| `public/expansion/catalog.css`・`catalog.js` | 図鑑の配置、カード表示、検索、絞り込み、ページ切替、詳細表示。                      |

本体も `index.html` から共有トークンを読み込む。旧 `shokudo.css` は削除し、新しいテーマへ置き換える。旧テーマを残したまま、さらに後掛けする構成にはしない。既存の機能ごとの配置CSSは保ち、色と操作面の一貫性は共有トークンと本体・Journeyのテーマで管理する。

新しいレシピ、なかま、アイテムを追加するときも、一覧の密度や操作色を種類ごとに増やさない。内容の多様さは絵と設定で見せ、遊び方の手掛かりは同じ位置、同じ言葉、同じ色で保つ。
