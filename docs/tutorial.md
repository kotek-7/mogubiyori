# チュートリアル設計

## 目的

初めて遊ぶ人が、自炊の記録から成長・出会い・収集・継続へつながる仕組みを理解できるようにする。最初の4章では操作と結果を確かめ、最後の章では3日間の連続記録が伸びる様子を自動再生で見る。

最初のなかまを選んだ後に開始する。画面には進み具合を表示する。1章では自分の料理写真を撮るよう案内し、2〜4章では「操作の練習」、最後の章では「自炊の記録例」を表示する。もぐは言葉を話さず、姿や動きで反応する。操作ボタンは動作、見出しや結果表示は仕組みと変化を伝える。育った姿は成長画面・成長一覧・来客画面ともシルエットだけを見せ、本編で発見する楽しみを残す。うまれたての姿は通常の色で表示する。

## 5章の操作と結果

| 章                    | 操作                                                                                               | 結果                                                                |
| --------------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| 1. ごはんをあげる     | 料理を撮影・撮影済みの写真を選択（なければサンプル写真）→写真を確認→ごはんをあげる→食事を見る      | 満腹・45 XP・成長ゲージの増加                                       |
| 2. 姿を育てる         | 2段階の成長を見る                                                                                  | うまれたてから輪郭が変わる。育った姿はシルエットで表示              |
| 3. なかまをふやす     | 育った子に給餌→匂いの先を見る→気づいた子を近くに呼ぶ→給餌→ひろばに呼ぶ                             | 食事の匂いが来客を呼び、給餌でなかまになり、その子も育てられる      |
| 4. 料理カードを集める | カレーの例で撮影を練習→写真を記録→カード獲得→ずかんに追加されたカレーを確認→未獲得のおにぎりを開く | 自炊の記録がカードと70コインになり、ずかんから次の料理を探せる      |
| 5. 自炊を続ける       | 未記録から1日目・2日目・3日目の記録を自動再生で見る                                                | 日付の枠が埋まる→連続日数が増える→3日連続ボーナス30コインの順で演出 |

「あそびかたガイド」はシステムの案内として場面の直下に置く。短い説明と、その場で行う操作を同じパネルにまとめる。匂いに気づく場面など、因果関係を伝える説明は操作するまで残す。もぐに人間のセリフは付けない。

3章では匂いに誘われたもぐが画面外から歩いて登場し、さらに近くまで歩いてくる。到着してから次の操作へ進める。章末では「わんぱくまで育つと別のもぐが来訪し、ごはんをあげるとなかまにできる」という条件を振り返る。

1章の「料理の写真を撮る」は端末の写真入力を開き、対応端末では背面カメラを使う。「撮った写真を選ぶ」から撮影済みの写真も選べる。今料理の写真を用意できない人は「サンプル写真を使う」で用意されたカレーの写真を選び、同じ手順へ進める。サンプルには確認画面で「サンプル写真」と表示する。自分の写真は本編と同じ処理でJPEG・PNG・WebPを読み込み、長辺800px以下に縮小する。写真を選ばず入力を閉じた場合は現在の画面と写真を保つ。読込失敗は画面内で案内し、別の写真やサンプルを選び直せる。

確認画面の「この写真を使う」で、お腹を空かせたなかまが待つ画面へ進む。選んだ写真は給餌中も表示する。「ごはんをあげる」を押してから食事とXP獲得へ進み、料理の撮影・確認・給餌を順に体験する。

4章は操作前から練習用のイラストであることを示す。「この例で撮影を試す」を押すと、カメラでカレーを捉えてシャッターを切る1.6秒のカットを挟み、写真の例を確認する画面へ進む。ずかんでは追加されたカレーだけを最初に強調し、そのカードを押して確認してから、おにぎりのレシピを開けるようにする。低モーション設定では歩行と4章の撮影の動きを省略する。

章内の操作はガイド内の黄色いボタン。章を終えたときだけ、画面下部に緑色の「次の章へ」と次章名を表示する。最後は「ひろばへ」で通常のゲーム画面へ移り、写真入力を自動では開かない。

最後の章は記録ボタンを置かず、開始時と各日の演出後に0.35秒の間を置いて翌日の記録へ進む。あそびかたガイドは開始から終了まで同じ説明を表示し、読む時間を確保する。3日目の報酬演出が終わると「ひろばへ」を表示する。低モーション設定では各日の動きを省略し、日ごとの間は残す。中断・前の章への移動では自動再生を止め、戻ると未記録から再生する。

材料・調理時間・作り方とカード報酬は本編と同じレシピ定数を参照する。1章では実際の写真入力を使い、サンプルを選んだ場合はその旨を表示する。4章の撮影練習では料理のイラストであることを案内する。クリック・タップ・キーボードで操作でき、ドラッグを必須にしない。読み上げと低モーション設定に対応する。

## 通常画面での案内

最後の章では、作った料理を「記録」で、7日間の自炊を「レポート」で見返せることも案内する。本編の食後には両画面へのリンクと、下のメニューからいつでも閲覧できる説明を表示する。「あそびかた」にも閲覧・編集・レポートの説明と入口を置く。

初回5章を終えた後は、ひろばの実際の「ごはんをあげる」を強調する。写真選択・食卓での案内を経て実際に食事を記録し、食後は成長確認とずかんの操作を案内する。専用の練習には戻さず、通常の操作を行うことで案内が進む。ガイドは閉じることもできる。

進捗は `tutorial.homeGuide` の `meal` → `growth` → `book` → `done` で保持する。既存ユーザーやチュートリアルの再体験では自動的に案内を開始しない。実際の給餌は通常の処理を一度だけ行い、ガイドが報酬を重ねて付与することはない。

本編でも、その日最初の自炊では記録枠→連続日数の順に表示する。3日連続・7日ごとの節目では、続けて実際に付与したボーナスを表示する。同じ日に追加で食事をあげても連続記録の演出を繰り返さない。練習と本編は同じ表示部品を使う。

## 練習と本編の分離

練習の食事、成長、加入、カード獲得、連続日数は画面内の一時状態で表現する。本編の給餌処理は呼ばず、XP・食事履歴・なかま・カード・通貨・日付・連続記録を更新しない。通常のログイン報酬はチュートリアルの報酬とは別に扱う。

1章で撮影・選択した写真も、その章の一時状態だけに保持する。写真のアップロード・料理の自動認識・本編の食事記録は行わない。中断・再読み込み・章の移動では破棄し、再開時や再体験では写真を選ぶところから始める。

永続化するのは `GameState.tutorial` の `version: 1`、`step: 0〜4`、`status` と、本編の案内を始めた場合の `homeGuide`。新規ゲームは `active` で始め、なかまの選択後に表示する。本編の初回記録は通常どおり45 XPで、最初の姿のまま。練習で見た成長や加入は付与しない。

## 一時停止と復帰

| 状態        | 表示と復帰                                                                                                               |
| ----------- | ------------------------------------------------------------------------------------------------------------------------ |
| `active`    | 現在の画面を表示する。再読み込み後も保存された `step` から始める。                                                       |
| `paused`    | 中断ボタン・「ひろばを見てみる」・Escapeで移行する。ひろばまたは設定の「チュートリアルを続ける」から同じ画面を再開する。 |
| `completed` | 最後まで体験すると移行する。自動表示せず、設定の「チュートリアルをもう一度」から再生できる。                             |

5章の保存は章単位。中断・再読み込み・前の画面への移動では、その画面内の操作結果を初期状態に戻す。再開時に前の操作を覚えていなくても、その場の操作からやり直せる。

チュートリアル情報を持たない既存セーブは、すでになかまがいれば `completed` として扱う。既存の進行を中断して自動表示しない。完了後の再生は一時的な状態で動かし、完了フラグを戻さず、終了時はひろばへ戻る。

## 公式資料の観察と本作の判断

以下は設計の参照であり、チュートリアルの効果を実証するデータではない。

- **桜井政博氏の動画で確認できること:** 通常のゲームを進めながら操作を覚える導入、操作対象の近くに示す案内、必要な操作を使うことで進める場面を紹介している。説明が作業になり、ゲーム開始を遅らせないことにも触れている。[自然なチュートリアル](https://www.youtube.com/watch?v=L1Su0aajYFA) の公開字幕を確認。**本作の判断:** 仕組みを体験する5章の後は通常画面へ移し、給餌・写真記録・成長・ずかんを実操作で覚える。

- **任天堂で確認できること:** 開発者インタビューでは、小さな機能を完成させる体験の積み重ねと、中断後もその場の指示で進める設計を説明している。[『はじめてゲームプログラミング』開発者インタビュー](https://www.nintendo.com/jp/interview/awuxa/03.html) **本作の判断:** 各画面で操作と結果を一組にし、画面単位で再開できる構成にする。
- **Pikmin Bloomで確認できること:** 公式ヘルプでは、エキスを与えると花が咲き、花びらを集め、その花びらを花植えに使う連鎖を説明している。[Pikmin Bloomのあそびかた](https://niantic.helpshift.com/hc/ja/23-pikmin-bloom/faq/2854-how-to-play-pikmin-bloom/) **本作の判断:** ごはんをあげる→反応を見る→XPやカードを得る、という操作と結果のつながりを先に体験させる。
- **Pokémon Sleepで確認できること:** 公式サイトでは、夜の睡眠記録、朝の寝顔収集、昼のカビゴン育成を一日の循環として紹介している。[Pokémon Sleepの一日](https://www.pokemonsleep.net/pokemon/) **本作の判断:** 自炊記録を成長・収集につなげ、最後に3日間の記録の変化を見せて次の自炊へ結びつける。

これらの理由や参照元は設計資料に留め、ゲーム画面の説明を増やすためには使わない。
