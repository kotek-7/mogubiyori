# 大規模コンテンツパック：町の食堂と料理図鑑

ゲーム本体の10レシピ・6種のなかま・7アイテムに追加するための独立パック。プレビューは `/expansion/index.html`。本体の初期選択画面・ずかんから開ける。既存のセーブデータは書き換えない。

## 収録範囲

| 種類           | 新規追加数 | 内容                                                                 |
| -------------- | ---------: | -------------------------------------------------------------------- |
| レシピカード   |        300 | 分量、手順、時間、難易度、収集レア度、コツ、検索タグ、道具、固有 SVG |
| なかま         |         36 | 性格、生息地、好物、会話4種、出会い条件、3段階の成長                 |
| 成長イラスト   |        108 | 各なかまの幼少・成長中・成体                                         |
| 着せ替え帽子   |         36 | 頭部への重ね合わせに対応した透明 SVG                                 |
| ひろばの背景   |         36 | キャラを置く中央を空けた場面 SVG                                     |
| キービジュアル |          1 | 内蔵 imagegen による食堂のイラスト                                   |

料理の内訳は、ごはん35、麺30、汁もの30、主菜75、副菜75、朝ごはん30、おやつ25。全て1人分の独自原稿。料理名だけを入れ替えた機械的な組み合わせ展開は使用しない。実調理での検証はまだ行っていない。食物アレルギー対応・栄養効果の保証はしない。

## 現時点で使えるもの

- 全300品を検索・絞り込みして材料と手順を読める図鑑。
- 36種のキャラそれぞれの成長3段階を切り替えるプレビュー。
- 帽子とひろばを任意の新キャラと重ねて確認するプレビュー。
- 名前・材料・道具・タグの検索、かなの正規化、分類・難易度・時間の複合絞り込み。
- 1ページ24件の表示、画面外の画像の遅延読み込み。
- 既存アプリの新配色、図鑑へのリンク。

新しい300カードの獲得、36種の実際の加入、72アイテムの購入は、準備パックからゲーム本体へ接続する次の実装に分離してある。このページで購入・給餌・加入状態は変更しない。既存の育成・ストリーク・コイン処理は維持している。

## ファイルと再生成

原稿は `content/expansion/recipes/*.json`、`characters.json`、`items.json`。配信形式は `public/expansion/catalog.json`。`manifest.json` に版数、件数、カタログ SHA-256、原稿・描画器のハッシュ、画像の出所を持つ。通常の `npm run build` / `pnpm run build` でも検証が走り、原稿を変えたまま配信用データの再生成を忘れた場合はビルドを止める。

```sh
# 原稿を編集した後、配信用カタログと料理SVGを再生成する
npm run content:build
# 参照・件数・重複・各項目を検証する
npm run content:check
npm test
npm run lint
npm run build
npm run test:e2e
```

原稿をスクリプトから再作成する場合のみ、次を実行する。JSONへの手修正を上書きするため、通常のビルドでは実行しない。

```sh
python3 scripts/content/author-staples.py
python3 scripts/content/author-mains.py
python3 scripts/content/generate-companions-items.py
npm run content:build
```

料理SVGは `scripts/content/recipe-art.mjs` と専用の `dessert-art.mjs`・`savory-art.mjs`、料理ごとの器・形・具材メタデータから生成する。300ファイルは300回の画像モデル出力ではない。料理の原画をさらに個別に磨く場合は、描画規則または料理のメタデータを編集する。生成済みSVGへの直接編集は次回の `content:build` で上書きされる。形状を共有する料理もあるが、画像パスを全て固有に持つ。

## 本体への取り込み方

`src/content/expansion.ts` に型と非同期ローダー、`src/content/adoption.ts` に重複を拒否する `mergeById`、既存 `Recipe` への変換 `adaptRecipe`、来客候補・アイテムの条件判定がある。段階的な接続に使う。

1. 読み込んだ `catalog.recipes.map(adaptRecipe)` を既存レシピに `mergeById` で追加する。既存IDは改名しない。
2. `Recipe` に `artPath` などの表示メタデータを合流させ、カードの画像を新SVGに切り替える。`sample` は旧描画器向けの互換項目であり、正確な料理画像は `artPath` にある。
3. 給餌画面の単一 select は300件に膨らませず、図鑑と同じ検索・絞り込みから選択した `recipeId` を渡す。
4. SpeciesId の閉じた6種 union は、登録済みIDのカタログ参照へ変更する。保存データのIDは読み込み時に照合し、不明IDを壊さず別に保持する。
5. 新キャラは stage 0/1/2 の `artPath` で表示する。来客は `availableVisitors` で上限3匹まで取り出す。`discovery` は先の目標を提案する条件で、既に仲間になったキャラを取り上げる条件にはしない。
6. `items` の `unlock` は売り場の発見条件。価格と装備は既存の残高確認・所有確認を通す。帽子は300×300の頭部レイヤー、背景は800×600の背面レイヤーとして描画する。各成長段階の `stages[].renderSpec.hatTransform` を SVG の translate/scale に適用する。頭の位置が特殊な種にも個別のアンカーを用意している。

## スケーリング時の仕様判断

- **難易度とレア度を別に持つ。** 現実の調理の難しさと収集上の特別感を同一視しない。
- **未獲得レシピも全文を読める。** 料理を作る動機を獲得前から用意する。
- **キャラの好物は探索のヒント。** 苦手食材や繰り返し料理による強い罰、新たな栄養ノルマは追加しない。
- **キャラとレシピの追加でXP曲線を変えない。** 1匹を育てる体験は保ち、横方向の発見を増やす。
- **化粧アイテムは能力を変えない。** コレクション単位で少しずつ見せ、最初から72個を買い物画面に並べない。
- **履歴に画像データを埋め込まない。** ゲーム進行はIDで参照し、素材は版付き静的資産として配る。
- **セーブの版数と素材の版数を分ける。** 素材追加のたびにセーブ全体の移行を要求しない。
- **数千件ではカタログを章ごとに分割できる。** 300件時点では依存を増やさず、JSONと静的画像で完結させる。

## 表現の方針と出所

[アートディレクション](../content/expansion/art/direction.md)に配色と採用理由を記載。既存SVGを拡張したオリジナルのコード描画と、内蔵imagegenで作成した食堂のキービジュアルを使用する。外部サイトの料理写真や既存キャラ素材は同梱していない。

内蔵imagegenの最終プロンプトは `content/expansion/art/neighborhood-table.prompt.txt`、生成画像は `public/expansion/assets/scenes/neighborhood-table.png`。新しい図鑑の画像・原稿・設定はすべてリポジトリ内に保存する。
