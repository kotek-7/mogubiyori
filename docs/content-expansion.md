# 大規模コンテンツパック：町の食堂と料理図鑑

レシピ300種・なかま36種・アイテム72種の追加コンテンツ。レシピは既存10種と合流し、本体で全310種を選択・獲得できる。既存のカードIDとセーブデータは維持する。追加のなかま・アイテムは `/expansion/index.html` でプレビューできる。本体のなかま6種・アイテム7種への追加採用は未実装。

## 収録範囲

| 種類           | 新規追加数 | 内容                                                                 |
| -------------- | ---------: | -------------------------------------------------------------------- |
| レシピカード   |        300 | 分量、手順、時間、難易度、収集レア度、コツ、検索タグ、道具、固有 SVG |
| なかま         |         36 | 性格、生息地、好物、会話4種、出会い条件、5段階の成長                 |
| 成長イラスト   |        180 | うまれたて・ちびっこ・わんぱく・おとな・とっておき                   |
| 着せ替え帽子   |         36 | 頭部への重ね合わせに対応した透明 SVG                                 |
| ひろばの背景   |         36 | キャラを置く中央を空けた場面 SVG                                     |
| キービジュアル |          1 | 内蔵 imagegen による食堂のイラスト                                   |

料理の内訳は、ごはん35、麺30、汁もの30、主菜75、副菜75、朝ごはん30、おやつ25。全て1人分の独自原稿。料理名だけを入れ替えた機械的な組み合わせ展開は使用しない。実調理での検証はまだ行っていない。食物アレルギー対応・栄養効果の保証はしない。

## 現時点で使えるもの

- 本体の図鑑と食卓で共通に使う、全310品のレシピ検索一覧。
- 名前・材料・タグの検索、かなの正規化、分類・難易度・時間・カード獲得状態の複合絞り込み。
- 1ページ24件の表示、料理画像の遅延読み込み。
- 未獲得の料理も材料・分量・手順・コツ・道具を読み、食卓へ進めるレシピ詳細。
- 追加300種の給餌・カード獲得・初回コイン報酬・保存と再読み込み・写真判定候補への接続。
- 追加料理の固有SVGを、詳細・獲得済みカード・食卓・獲得演出・写真のない食事履歴に表示。
- 36種のキャラそれぞれの成長5段階を切り替えるプレビュー。
- 帽子とひろばを任意の新キャラと重ねて確認するプレビュー。

`/expansion/index.html` はなかまのプレビューから始まり、「料理カード」リンクは本体の `/#book` へ移動する。料理の検索と獲得状態は本体の図鑑にまとめている。36種の実際の加入と72アイテムの購入は未接続で、このプレビューでは購入・給餌・加入状態を変更しない。

## ファイルと再生成

原稿は `content/expansion/recipes/*.json`、`characters.json`、`items.json`。本体のレシピは `shared/content/recipes.ts` が料理原稿2ファイルを直接取り込む。プレビュー用の配信形式は `public/expansion/catalog.json`。`manifest.json` に版数、件数、カタログ SHA-256、原稿・描画器のハッシュ、画像の出所を持つ。通常の `pnpm build` でも検証が走り、原稿を変えたまま配信用データの再生成を忘れた場合はビルドを止める。

```sh
# 原稿を編集した後、配信用カタログと料理SVGを再生成する
pnpm content:build
# 参照・件数・重複・各項目を検証する
pnpm content:check
pnpm test
pnpm lint
pnpm build
pnpm test:e2e
```

原稿をスクリプトから再作成する場合のみ、次を実行する。JSONへの手修正を上書きするため、通常のビルドでは実行しない。

```sh
python3 scripts/content/author-staples.py
python3 scripts/content/author-mains.py
python3 scripts/content/generate-companions-items.py
pnpm content:build
```

料理SVGは `scripts/content/recipe-art.mjs` と専用の `dessert-art.mjs`・`savory-art.mjs`、料理ごとの器・形・具材メタデータから生成する。300ファイルは300回の画像モデル出力ではない。料理の原画をさらに個別に磨く場合は、描画規則または料理のメタデータを編集する。生成済みSVGへの直接編集は次回の `content:build` で上書きされる。形状を共有する料理もあるが、画像パスを全て固有に持つ。

## 本体への接続

### 接続済みのレシピ

`shared/content/recipes.ts` は既存10種を `legacyRecipes` として保持し、料理原稿2ファイルを `adaptRecipe` で変換して `mergeById` で合流させる。全310種の `recipes`、表示型 `Recipe`、分類名 `recipeCategories` を公開する。`shared/content/catalog.ts` はゲームから使うレシピ参照と、採用済みのなかま・成長段階・アイテムを提供する。

登録は同期的に完了するため、`shared/game/stateCodec.ts` が保存済みカードを検証する時点で追加300種のIDも参照できる。ブラウザの保存入口は `src/app/game/gameStorage.ts`、写真判定は `worker/recognition/recognition.ts` で、どちらも同じ登録内容を使う。カードは給餌時に初めて獲得し、同じ料理のカード報酬は再読み込み後も重ねて付与しない。

`src/features/collection/`に図鑑の画面、`RecipeBoard`・`RecipeDetail`・`RecipeBrowser`とCSSをまとめる。`RecipeBrowser` は食卓の料理選択でも共用し、検索・絞り込み・24件ごとのページ送りに対応する。共通描画の `src/ui/art/RecipeArt.tsx` は追加料理の `artPath` を描画し、既存料理には `sample` の描画器を使う。分量・説明・コツ・道具・タグも `Recipe` に保持する。

型定義はブラウザに依存しない `shared/content/types.ts` に置く。`src/features/collection/expansion.ts` は型を再公開し、プレビュー用カタログの非同期ローダーを提供する。`shared/content/adoption.ts` にはレシピ変換のほか、将来の来客候補・アイテム条件判定がある。

生成物と本体の整合性は `tests/integration/content.test.ts` と `tests/integration/recipe-adoption.test.ts` で検証する。原稿の `content/`、配信用の `public/expansion/`、生成・検証手順の `scripts/content/` はそれぞれの役割を保つ。

### なかま・アイテムの今後の取り込み

1. SpeciesId の閉じた6種 union は、登録済みIDのカタログ参照へ変更する。保存データのIDは読み込み時に照合し、不明IDを壊さず別に保持する。
2. 新キャラは stage 0/1/2/3/4 の `artPath` で表示する。来客は `availableVisitors` で上限3匹まで取り出す。`discovery` は先の目標を提案する条件で、既に仲間になったキャラを取り上げる条件にはしない。
3. `items` の `unlock` は売り場の発見条件。価格と装備は既存の残高確認・所有確認を通す。帽子は300×300の頭部レイヤー、背景は800×600の背面レイヤーとして描画する。各成長段階の `stages[].renderSpec.hatTransform` を SVG の translate/scale に適用する。頭の位置が特殊な種にも個別のアンカーを用意している。

## スケーリング時の仕様判断

- **難易度とレア度を別に持つ。** 現実の調理の難しさと収集上の特別感を同一視しない。
- **未獲得レシピも全文を読める。** 料理を作る動機を獲得前から用意する。
- **キャラの好物は探索のヒント。** 苦手食材や繰り返し料理による強い罰、新たな栄養ノルマは追加しない。
- **キャラとレシピの追加でXP曲線を変えない。** 1匹を育てる体験は保ち、横方向の発見を増やす。
- **化粧アイテムは能力を変えない。** コレクション単位で少しずつ見せ、最初から72個を買い物画面に並べない。
- **履歴に画像データを埋め込まない。** ゲーム進行はIDで参照し、素材は版付き静的資産として配る。
- **セーブの版数と素材の版数を分ける。** 素材追加のたびにセーブ全体の移行を要求しない。
- **数千件ではカタログを章ごとに分割できる。** 300件時点では依存を増やさず、JSONと静的画像で完結させる。

## 表現の方針と出所

[アートディレクション](../content/expansion/art/direction.md)に配色と採用理由を記載。既存SVGを拡張したオリジナルのコード描画と、内蔵imagegenで作成した食堂のキービジュアルを使用する。外部サイトの料理写真や既存キャラ素材は同梱していない。

内蔵imagegenの最終プロンプトは `content/expansion/art/neighborhood-table.prompt.txt`、生成画像は `public/expansion/assets/scenes/neighborhood-table.png`。新しい図鑑の画像・原稿・設定はすべてリポジトリ内に保存する。
