# ひとさじの体験検証

## 確認したいこと

開いてすぐ記録を始められるか、写真1枚で終えられるか、達成を見て明日も戻りたいと思えるかを観察する。未記録日の後に再開できることも重視する。

## 15分のセッション

1. **生活の状況を聞く（3分）**：直近に自炊をやめた日はいつか。そのとき食べたもの、考えた時間、買い物や調理の負担を具体的に聞く。
2. **説明せず一周してもらう（4分）**：料理を作り終えた場面から、写真の記録と達成確認を経てホームに戻る。写真がなければサンプルの一皿を使う。
3. **1つだけ仕様を変える（4分）**：実験室で比較する項目を1つ選ぶ。画面に戻り、同じ状況でどちらを選ぶかを観察する。
4. **続かなかった日の翌日を試す（2分）**：実験室の翌日ボタンで未記録日を越える。何を感じ、次にどこを押したくなるかを聞く。
5. **メモを残す（2分）**：行動・発言・解釈を分けて記載し、設定と一緒に書き出す。

## 再現しやすいシナリオ

| 状況                 | 操作                                             | 確かめること                           |
| -------------------- | ------------------------------------------------ | -------------------------------------- |
| 疲れて帰宅した       | 「献立に迷ったら」で5分以内に変更                | 候補を見て、作れそうと思えるか         |
| 冷蔵庫を使い切りたい | 献立ノートで食材を選び、買い足しなしに絞る       | 食材登録の手間に見合うか               |
| すでに料理した       | 「今日の一皿を残す」から写真だけで記録           | 追加入力せず記録と達成確認ができるか   |
| 見せる自信がない     | 「自分だけ」で記録                               | 公開せずに食卓を見られることが伝わるか |
| 同じ料理が続いた     | 同じジャンルを記録し、記録詳細で加点・減点を比較 | 次も作ろうと思えるのはどちらか         |
| 忙しい日がある       | おやすみチケットを使い、翌日に進む               | 保護の意味と残数が理解できるか         |
| 昨日作れなかった     | 記録せず翌日に進む                               | 再開する一歩が見つかるか               |
| 週に数回だけ作りたい | 週3日の目標に変更                                | 毎日方式より生活に合うか               |
| 初めて使う           | 実験室で「はじめての自炊」を開始                 | 何をするサービスか単体で理解できるか   |

状態を初期化すると、料理と写真が置き換わる。比較設定とメモは残る。複数条件を同時に変更すると差の理由がわからなくなるため、比較は一度に1項目を基本とする。

## 記録する項目

- 観察した状況、使った設定、手元の食材と時間
- 最初に押したボタンと、記録を始めるまでの時間
- 写真選択から記録完了までの時間と入力のつまずき
- 達成画面で気づいたこと、明日も開きたいか
- 献立の補助を使った場合は、決定までの時間と変更回数
- 公開範囲の選択と、そうした理由
- 休んだ翌日に再開したいか、その理由
- 実際の操作、本人の発言、検証者の解釈

実験室のJSONには設定、検討メモ、記録と主要操作の履歴が入る。写真データは含まない。全クリックや操作時間を自動計測する分析基盤ではないため、所要時間は別に観察する。

## 判断を急がないこと

一度の操作体験では継続率や事業性はわからない。方向性を絞った後は、実際に自炊する人に一定期間使ってもらい、初回記録、翌週の再訪、未記録日の後の復帰を追う。

支払い意思は機能への好意と区別する。普段、献立・買い物・食事に何の負担があり、既に時間や費用を使っているかから確かめる。サンプルの投稿への反応を、実際の友達との関係の効果として扱わない。
