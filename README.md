# もぐ日和

**きみのごはんで、なかまが育つ。**

公開先：[mogubiyori.kotek7.com](https://mogubiyori.kotek7.com/)。育成記録と写真はアカウントごとにクラウドへ保存します。

自分で作った料理を、小さななかまと分けあう育成ゲームです。写真を届けると成長し、大きく育った子のもとには新しいお客さんがやってきます。

**なかまと出会う → 写真を選ぶ → 食卓へ → ごはんをあげる → ひろばへ。**

## 起動

Node.js 22.12以降とpnpm 12.5.1を使います。依存の正本は`pnpm-lock.yaml`です。

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Reactの画面とCloudflare Workerを、Vite pluginで同じサーバーから動かします。別のAPIサーバーやプロキシ設定は不要です。Supabase未設定の開発環境は`local`モードで、これまでのブラウザ内の記録を引き継ぎます。

スマートフォンではPCと同じネットワークに接続し、`pnpm dev --host 0.0.0.0`で表示されるNetwork URLを開きます。端末間通信が制限されたゲストWi-Fiでは接続できません。

写真の自動判定にはCloudflareログインが必要です。Workers AIは開発中もアカウントの利用枠を使います。

```sh
pnpm exec wrangler login
pnpm dev:cloudflare
```

8787番で画面・APIを起動し、リモートのWorkers AIへ接続します。通常の`pnpm dev`ではリモートbindingを無効にしているため、Cloudflareへログインせずに起動できます。判定できないときも料理の手動選択とサンプル写真での体験は使えます。

## 認証・クラウド保存

`.env.example`を参考にSupabaseのURLと公開キーを設定すると、`cloud`モードになります。初回は自動で匿名ユーザーを作り、次回から同じセッションを復元します。認証方法を選ぶ画面を挟まずに遊べて、育成記録はユーザーごとにDBへ、写真はprivate Storageへ保存します。`VITE_GAME_MODE=local`を明示すると端末内保存で開発できます。

Google OAuthを設定した環境では、設定画面から任意で連携できます。設定は最初のなかまを選ぶ前にも開けます。「Googleと連携する」は現在の匿名ユーザーにGoogleを追加し、そのままの記録を引き継ぎます。別端末などで既存の記録を開くときは「Googleで続きから」を使います。現在の記録とGoogle側の記録は自動で合算しません。未設定の環境ではGoogleの操作を表示しません。匿名のままブラウザのサイトデータを消すと同じユーザーへ戻れなくなります。

Worker用のローカル設定は`.dev.vars.example`を参照してください。DB migration、Authの設定、公開時のSecretは[実行環境と接続手順](docs/infrastructure.md)に記載しています。クラウド接続に失敗した場合はエラーを表示し、端末内の別ゲームへ自動で切り替えません。

## ビルド・公開

```sh
pnpm build
pnpm preview
# 公開先・DB・認証・Secretの準備後に実行
pnpm deploy
```

ビルドは画面を`dist/client/`、Workerと生成設定を`dist/mogubiyori/`へ出力します。`wrangler deploy`はCloudflare Vite pluginの生成設定を使い、Workerと静的ファイルをまとめて配信します。ブラウザ用の`VITE_*`設定はビルド時に確定します。通常のNode.jsサーバーは本番で起動しません。[Cloudflare Vite pluginの構成](https://developers.cloudflare.com/workers/vite-plugin/tutorial/)

## 写真から料理と食事内容を読み取る（Gemma 4）

Cloudflare Workers AIの`@cf/google/gemma-4-26b-a4b-it`で主な料理の候補を最大3件取得し、主菜・ごはん・副菜など最大12品の名前・食品群・量を食卓の「食事の内容を確認」へ自動入力します。違う場合は候補や「料理を選ぶ」の検索一覧、食事内容の各欄で変更できます。追加の確認画面は挟まず、「ごはんをあげる」で食事内容を保存し、カードを確定します。量は少なめ・ふつう・多めの目安で、判断できなければ未設定にします。食事の時間や自炊かどうかは写真から推測しません。

候補は`shared/content/recipes.ts`の612種のレシピと、`shared/content/dishes.ts`の47種の料理分類から選びます。ごはん・麺・パンや粉もの・肉・魚介・卵や豆・野菜や副菜・汁物や鍋・おやつや果物・その他のおかず・飲みもの・盛り合わせの12グループで整理し、具体的なレシピを特定できなくても、パスタ・カレー・パン・揚げ物などの名前で記録できます。「料理を選ぶ」はカテゴリごとにレシピを2品、料理分類を最大4種類ずつ最初から表示します。「ごはん・丼」「麺」などを押すと、そのカテゴリのレシピと料理分類をまとめて探せます。名前・材料・読み・別名の検索欄も共通です。カテゴリ内や検索結果では、レシピを24品、料理分類を12種類ずつ表示します。カタログ外の料理も、写真から分かる名前・食品群・量を食事内容に反映します。種類での記録は通常の経験値と毎日の報酬を獲得し、料理カードは具体的なレシピを選んだ場合に獲得します。

認識には全レシピと全種類のカタログを1回のモデル呼び出しで渡します。分類名・検索語をまとめた配列形式で、繰り返す項目名を省いて入力を抑えます。写真で確認できる範囲の料理名を選び、具材・味付けが不明ならパスタや煮物など広い種類を使います。ペペロンチーノやカルボナーラなどの具体名はレシピカードに収め、料理分類ではパスタとして扱います。`content/legacy-meal-dishes.json`の旧分類は保存済みの記録・送信待ちの記録の互換性のために参照し、選択一覧や認識候補には出しません。候補の追加は対応範囲の拡張であり、実際の認識率を保証するものではありません。

写真の検出中は文章の横で三点リーダが控えめに明滅し、食卓へ進んでも表示を続けます。動きを減らす設定では点を静止させます。通信失敗や判定待ちでも手動で進められ、手動で選んだ料理や修正した名前・食品群・量・副菜を遅い判定で上書きしません。写真を差し替えると古い写真の自動入力を取り除き、体験を中止すると下書きを破棄します。どちらも古い判定結果を後から反映しません。写真は端末で縮小してからWorkerへ送信します。

「料理の写真を撮る」はブラウザ内でカメラを開きます。外部カメラアプリへ切り替えず、撮影した画像を長辺800px以下にして読み込みます。撮影・キャンセル・画面を離れる操作でカメラを停止します。カメラを使えない場合も「撮った写真を選ぶ」から保存済みの写真を選べます。写真ファイルも向きと縦横比を保ち、読み込み時に縮小サイズを指定します。

[Gemma 4のモデル仕様](https://developers.cloudflare.com/workers-ai/models/gemma-4-26b-a4b-it/)、[Workers AIの料金](https://developers.cloudflare.com/workers-ai/platform/pricing/)

## あそびかた

- **ひろば**：最初のなかまを選び、料理の写真でごはんをあげます。5段階で体形が変わり、新しいお客さんがフィールドに訪れます。お客さんを直接タップしてごはんをあげると、なかまになります。
- **ふれあい**：なかまをタップでつつく、指を滑らせてなでる、左右にこすってくすぐる、長押しで寄り添う、上にはじくと跳ねる、と触り方で反応が変わります。マウスでも同じ操作ができ、キーボードやボタンからも遊べます。性格・成長段階・満腹やおやすみの状態も表情と動きに反映されます。
- **ずかん**：育てたなかまと、初めての料理カードを集めます。カテゴリごとにレシピを2品ずつ表示し、気になるカテゴリを1回押すと一覧を広げられます。全612種から名前・材料で検索でき、調理時間・難しさ・獲得状態は「詳しく絞り込む」から指定できます。未獲得の料理も材料と手順を読んで食卓へ進めます。
- **おみせ**：食事記録やログインで貯まるコインで、帽子・首元・かばん・ひろばの背景を購入します。帽子と首元とかばんは同時に身につけ、部位ごとにきせかえできます。
- **毎日のごほうび**：ログイン、自炊、料理カード、継続日数に応じてコインを獲得します。ログインの20コインは保存後にコインが弾む演出で知らせ、約5秒で閉じます。チュートリアルや食事の途中では、通常画面に戻ってから表示します。
- **記録**：下のメニューから、作った料理を写真と日付で見返せます。「自炊を記録する」から今日の料理を追加でき、食事の時間、複数の料理、量、食品群は記録後も編集できます。
- **レポート**：下のメニューから、7日間のスコアグラフ・食品群の推移・自炊した日数と、選んだ日のバランスを確認できます。記録とレポートは同じ日付のまま行き来でき、ひろばや食後の案内からも開けます。

最初の成長は早くても3食目。初めての食事の後も「うまれたて」の姿を保ち、出会った姿はプロフィールで見返せます。

初回は、自炊がもぐの成長や新しい出会いにつながる[コンセプトを3画面で紹介](docs/concept-intro.md)してから、最初のなかまを選びます。紹介はスキップでき、読み終えたことを保存するので次回起動では繰り返しません。最初のなかまを迎えたら、チュートリアルで操作を練習できます。練習は本編の報酬や記録を変更せず、途中で休んで後から再開できます。写真選択・食卓・食事は、それぞれ独立した画面です。成長や新しいカードは一つずつお祝いします。食後のXP獲得や連続記録の更新は、結果を確認してボタンを押すまで表示します。

写真がないときはサンプルでも体験できます。料理の選択と名前は任意です。写真選択へ戻っても入力は保たれ、ごはんをあげる前なら中止できます。ジェム販売・追加は廃止し、既存セーブのジェム残高は読み込み時に同数のコインへ一度だけ移します。

成長・来客・翌日の空腹などの動作確認には、後述の隠しデバッグ設定を使います。通常の設定画面には日送り・育成変更・進捗リセットを表示しません。

## 保存と実装範囲

公開サイトはSupabaseの匿名認証・DB・private Storageを使う`cloud`モードです。Google連携も設定済みで、設定画面から任意で連携・記録の復帰を行えます。

`local`では記録・縮小写真・育成・購入状態を、このブラウザの`localStorage`（`mogubiyori-v1`）に保存します。再読み込み後も残りますが、端末間では共有されません。既存セーブは移行処理を通して読み込みます。

`cloud`では匿名ユーザーも含めてSupabaseへ保存し、操作IDによる再送処理とrevisionによる同時更新の検査を行います。XP・コイン・カードはWorkerが計算し、保存が確定した結果から演出します。Google連携後は別端末から同じアカウントで続けられる構成です。実際のGoogle認証と端末間の確認には接続先の準備が必要です。localの既存記録はそのまま端末に残り、cloudへ自動で取り込みません。

日付は日本時間を使い、デバッグ設定から進めた日数を加算します。自炊したかどうかは自己申告です。既存ローカルセーブのクラウド取込、下書きの再読み込み後の復元、プッシュ通知、実決済は未実装です。

食事スコアは食品の組み合わせの目安です。主食30点・肉魚卵豆30点・野菜40点を、判定できた食事で平均します。量や栄養素の摂取量は評価せず、食品群が不明な食事や未記録の日には点数を付けません。同じ食事を複数のもぐへおすそわけしても集計は1食のままで、記録の編集では受け取った報酬を変更しません。詳しくは[食事レポートの仕様](docs/meal-reports.md)を参照してください。

## デバッグ設定

ひろばなどの通常画面で、左上の「もぐ日和」を5秒以内に7回押すか、`Ctrl + Alt + D`を押すと開きます。チュートリアル・食事中・文字入力中にはショートカットを受け付けません。

- 保存先、ゲーム内の日付、進めた日数、更新番号の確認と保存データの再読み込み。
- 1日・7日の日送り。再読み込みや別端末でも日数を保持し、食事・連続記録・ログイン報酬もその日付で処理します。
- 加入済みのなかまを選び、5段階の成長段階に変更。経験値を各段階の開始値に合わせます。
- 体験用データへの置き換え、または初期状態へのリセット。確認後に記録を削除し、日付を実際の今日に戻します。会員プランとログイン状態は維持します。

`local`では常に利用できます。`cloud`ではWorkerの`DEBUG_TOOLS_ENABLED`が文字列`"true"`の場合だけ実行でき、現在の`wrangler.jsonc`では本番でも有効にしています。無効にする場合は`"false"`へ変更して再デプロイします。無効化だけでは既存の日付オフセットや育成状態は戻りません。

隠し操作は管理者認証ではありません。有効な環境では匿名ユーザーを含め、各ユーザーが自分のセーブデータを変更できます。サーバーで認証・操作の検証・同時更新の検査を行い、同じ操作IDの再送で二重適用しません。他ユーザーの指定や任意のセーブデータの送信は受け付けません。

## 会員プラン

画面右上の「プラスに加入」（有料会員は「プラス会員」）または設定の「会員プラン」で、無料・有料を切り替えられます。請求はモックで、料金は発生しません。localとcloudの両方でプランを保存します。

| 機能             | 無料                | 有料（もぐ日和プラス） |
| ---------------- | ------------------- | ---------------------- |
| 栄養レポート     | 今日を含む直近3日分 | 全期間                 |
| 新しいごはん記録 | 1日1回              | 1日何回でも            |
| 閲覧できるレシピ | 定番30品            | 全612品                |
| 広告             | サンプル広告を表示  | 非表示                 |

無料へ戻しても記録やカードは削除しません。食事そのものの履歴と、同じ食事を別のもぐに分ける操作は無料でも利用できます。既存セーブにプランがない場合は無料として扱います。

実決済と広告ネットワークは未接続です。実課金へ移行する際は、自由に変更できる `setSubscriptionPlan` を決済サービスの確認済み契約情報へ置き換えます。現段階のレシピとレポートの閲覧制限はアプリ画面に適用し、レシピ全件は配信ファイルに、食事データはユーザー自身の保存データに含まれます。

## コードの配置

画面・固有部品・CSS・単体テストは`src/features/<機能>/`にまとめています。`src/app/`はアプリの構成、route、dialogの切り替えを担当し、保存セッションとlocal/cloudの接続は`src/app/game/`に置きます。複数機能で使う描画や画面枠は`src/ui/`で共有します。

ブラウザとWorkerに共通のルールは`shared/game/`、採用コンテンツは`shared/content/`です。Worker側のゲーム操作とSupabase接続は`worker/game/`、料理認識は`worker/recognition/`に置きます。CSSは各機能の近くに置き、既存の適用順を保つため`src/app/styles.ts`から明示した順に読み込みます。

単体テストは実装に隣接し、機能や保存境界を横断するテストは`tests/integration/`、ブラウザ全体の検証は`tests/e2e/`と`tests/cloud/`に置きます。詳しい責務と開発時のルールは[アーキテクチャ](docs/architecture.md)を参照してください。

pnpm test

## ずかんと追加コンテンツ

追加602種のレシピは、本体の「ずかん → 料理カード」に統合しています。食卓でも同じ検索一覧から料理を選べ、初めてごはんをあげるとカードと報酬を獲得します。既存カードと食事記録はそのまま残ります。

追加予定のなかま36種・帽子と背景72種は、開発サーバーの `/expansion/index.html` で成長段階ときせかえをプレビューできます。このページの「料理カード」は本体のずかんへ移動します。帽子6点は本体のおみせで購入できます。残りの拡張アイテムの購入と、追加のなかまの加入は未接続です。素材の再生成・検証と採用状況は[追加コンテンツの仕様](docs/content-expansion.md)を参照してください。
